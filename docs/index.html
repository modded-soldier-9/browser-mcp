Autonomous Token Shield

Semantic & Viewport DOM Pruning

Raw webpage DOMs routinely surpass 300,000 tokens. Token Shield condenses pages into an accessible semantic tree, pruning off-screen nodes and mapping elements to monotonic handles ([e1]-[e43]).

  • 98.8% Token Savings: 142k tokens distilled to 1.6k
  • Spatial Viewport Pruning: viewport_only=true saves 50–70%
  • Handle Generation: Instant targeting with [e1] refs

Atomic Form Batching & Spooling

Rather than burning one LLM turn per input field, Browser Control dispatches entire forms atomically with event-loop pacing, with automatic disk spooling for massive payloads.

  • Single-Turn Batching: Fill 20+ fields in one request
  • Event-Loop Pacing: 35ms debounced React/Vue events
  • Disk Spooling: Payloads >2,500 tokens stored locally

Got Questions?

Frequently Asked Questions

Everything you need to know about architecture, privacy, and client support.

What is Browser Control and why was it rewritten in Rust?
Browser Control (formerly Browser MCP) is an open-source Model Context Protocol server that bridges AI assistants to your daily browser. It was rewritten from scratch as a standalone native Rust binary to eliminate Node.js dependencies, achieve sub-4ms cold startup, reduce idle memory to ~3.8MB, and introduce an autonomous Token Shield that protects LLM context windows from token exhaustion.
How does Browser Control differ from Playwright MCP and headless runners?
Unlike Playwright MCP, which spins up isolated headless profiles that hit bot verification and login walls, Browser Control connects directly to the Brave and Chrome tabs you are already signed into. It inherits your cookies, active logins, and 2FA authentication, allowing your AI assistant to act on private dashboards and SaaS tools without mock credentials.
Is my browsing data and token security protected?
Yes. Browser Control contains zero telemetry, zero analytics, and connects strictly over local loopback (127.0.0.1:9876-9895). It enforces strict Origin: chrome-extension://[a-p]{32} verification on incoming WebSockets to prevent unauthorized local process connections. Source code is completely open and auditable on GitHub.
How does 2FA assistance and CAPTCHA solving work?
When an automated task encounters a CAPTCHA or 2FA verification challenge, Browser Control invokes browser_ask_user to render an interactive in-browser dialog. The automation pauses cleanly until you approve or complete the step on your own screen, after which the agent resumes in the exact same tab.
Which AI coding assistants are supported?
Any assistant supporting standard MCP JSON-RPC over stdio works out of the box, including Claude Desktop, Cursor, Gemini/Antigravity, Windsurf, VS Code (Cline/Roo), Claude Code, OpenCode, and Zed. Run browser-mcp install to automatically configure all detected client configuration files.
